# Project Plan

Plan what should be built before implementation.

## Workflow

1. Recover existing project context before asking the user to repeat it.
2. Define objective, users, value proposition, constraints, revenue/operating goals, and non-goals.
3. Inspect existing code/assets/infrastructure when present.
4. Separate must-have MVP from later expansion.
5. Choose the smallest practical architecture.
6. Prefer existing, student-included, local, and verified-free resources before paid services.
7. Break work into milestones with dependencies.
8. For each milestone define deliverables, acceptance criteria, validation evidence, risks, and human-only blockers.
9. Identify secrets/accounts/legal/payment actions that must remain human-controlled.
10. Produce a clean execution handoff.

## Plan structure

Include current state, goal and success metrics, scope/non-scope, architecture, data/integration model, UX surfaces, security/privacy requirements, analytics/SEO/observability where relevant, milestones, prioritized tickets, test strategy, deployment/release strategy, cost/resource strategy, risks/blockers, and Definition of Done.

Do not silently start implementation when the user asked to plan first.
